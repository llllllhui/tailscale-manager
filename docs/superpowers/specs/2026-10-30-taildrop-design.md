# Taildrop 文件收发

用户在确认 v0.2.0 尚未包含文件收发后，要求补齐。本次直接完成界面、后台、验证、安装升级和 GitHub v0.3.0 发布。

## 使用体验

- 本人设备的「发送文件」按钮打开系统多选文件窗口，明确显示接收设备。
- 本次传输列表逐文件显示排队、发送中、完成、失败和取消；发送不阻塞网络管理，支持取消尚未完成的任务。
- 默认自动接收至系统下载目录下的 `Tailscale` 文件夹；可切换接收文件夹和开关自动接收，也可手动收取。
- 托盘提供发送文件、接收文件和打开接收文件夹；收到文件通过系统通知提示，点击可打开接收文件夹。
- 接收同名文件自动加编号；先完整保存并同步到磁盘，再从 Tailscale 收件箱删除；失败保留收件箱中的原文件。
- 只向 Tailscale 列出的个人文件接收目标开放发送，不把所有同一 tailnet 的设备视为可发送目标。禁用条件和权限错误在界面解释。
- 传输记录保留本次运行的最近 50 条，不将文件内容或路径写入 Git 仓库。

## 方案选择

1. 选择混合方案：官方 CLI 负责发送和取消进程；LocalAPI 负责设备发现、待收文件、流式下载和收件确认。能复用官方传输行为，同时获得准确的接收文件名及错误处理。
2. 完全使用 CLI 更少接口，但接收结果仅有给人看的文本日志，对包含换行或其他特殊字符的文件名不可靠。
3. 完全使用 LocalAPI 需要额外实现发送进度和进程取消语义，本次没有必要。

LocalAPI 仅通过现有 Unix socket 访问，不增加监听端口或新依赖。大文件流式处理，不完整装入内存。文件收发仅暴露给桌面消息桥，不接入开发用 HTTP 服务。

## 模块与边界

`taildrop.py` 独立于 GTK，封装 Unix HTTP 客户端、目标发现、收件、发送队列、取消和线程安全快照。`desktop.py` 负责系统文件选择器、目录选择器、托盘菜单和系统通知。`ui.html` 展示设备发送入口及收发面板。接收目录和自动接收偏好与现有窗口设置一起保存在用户配置目录。

## 验证

使用临时文件和模拟的 Unix socket 后台实际验证发送命令、接收字节、同名文件、异常中断、路径校验、确认失败重试及取消。图形检查使用替身，不向实际其他设备发送文件。真实守护进程只读验证可用设备和收件元数据。公开截图使用演示数据；构建、安装升级、发布和回下载校验 v0.3.0。
